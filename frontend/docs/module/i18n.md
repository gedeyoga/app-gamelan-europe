# Module: i18n — Brief

Dokumen ini mencatat implementasi **internasionalisasi (i18n)** frontend React memakai
`i18next` + `react-i18next`. Mengikuti konvensi `AGENTS.md` frontend.

## 1. Tujuan & Ruang Lingkup

- Menyediakan switch bahasa **EN ↔ ID** untuk seluruh teks generik frontend.
- Default `en`, support `en` + `id`, persist `localStorage` key `app.locale`.
- Backend message spesifik (`Invalid credentials`, `Validation failed`, field errors
  dari envelope `{ statusCode, message, errors }`) **tetap tampil apa adanya**;
  hanya pesan generik frontend yang diterjemahkan.
- **Routing tidak berubah** — tidak ada prefix locale di URL (`/`, `/users`,
  `/roles`, `/login` tetap sama). Ganti bahasa tidak navigasi ulang.

## 2. Routing

Tidak ada perubahan routing (`src/app/routes/index.tsx` tetap):

```
/ (ProtectedRoute → DashboardLayout → AppShell)
├── / (index → DashboardHomePage)
├── /users (UsersPage)
└── /roles (RolesPage)
/login (GuestRoute → LoginPage)
```

Wiring:

- `src/app/providers.tsx` — `import i18n from '@/i18n'` + `<I18nextProvider i18n={i18n}>` +
  `Suspense` fallback sederhana (`Loading... / Memuat...`).
- `src/features/dashboard/components/app-shell.tsx` — header kanan:
  `<LanguageSwitcher />` + `<ThemeToggle />` (`ml-auto flex items-center gap-2`).
  Dipilih header agar konsisten terlihat di semua halaman; sidebar footer tetap
  untuk identitas user saja.
- `tsconfig.app.json` — `resolveJsonModule: true` agar `import *.json` lolos typecheck.

## 4. Konvensi Keys

- Namespace = domain: `common`, `auth`, `dashboard`, `user`, `role`, `validation`.
- `defaultNS: 'common'`; panggil dengan prefix eksplisit bila lintas NS:
  `t('user:title')`, `t('validation:emailRequired')`, `t('common:actions.save')`.
- `common` berisi:
  - `actions.*`: `save/cancel/delete/create/search/retry/close/loading/edit/previous/next/saving/deleting`
  - `pagination.total` dengan plural (`_one`/`_other`) + interpolasi
    `{{count}} {{entity}} · page/halaman {{page}}`
  - `search.*`, `table.actions/actionsFor`, `empty.notFound` (`{{term}}`),
    `language.*`, `sort.by` (`{{column}}`)
- Tabel: header via `t('user:table.*')` / `t('role:table.*')`; empty-state bedakan
  `table.empty` vs `table.notFound` (`{{term}}` = `searchTerm.trim()`) + tombol reset.
- Status user: `t('user:statusOptions.<STATUS>', { defaultValue: <STATUS> })` agar
  badge ikut bahasa dengan fallback ke enum mentah bila key hilang.
  `role-table` tidak punya kolom status serupa — tidak perlu perubahan.
- Pagination: `entityName={t('user:title')}` agar total ikut bahasa.
  `entityName` di `DataTablePaginationProps` **wajib** (`entityName: string`,
  tanpa default `'data'`) agar tidak ada fallback Inggris diam-diam; semua callers
  (`users.tsx`, `roles.tsx`) sudah passing translated title.
- Bahasa Inggris (`en/`) adalah **sumber kebenaran**; `id/` wajib punya keys identik.
- Pengecualian proper-noun (§4a, diputuskan 2026-09-05): istilah produk/domain
  **tidak diterjemahkan** dan dipertahankan sama di `en` dan `id` agar konsisten
  dengan entitas backend + konsistensi UI:
  - `user:title` = `Users` (bukan `Pengguna`), `role:title` = `Roles` (bukan `Peran`);
  - `dashboard:nav.users` = `Users`, `dashboard:nav.roles` = `Roles`,
    `dashboard:title/nav.dashboard` = `Dashboard`;
  - `common:actions.edit` = `Edit` (bukan `Ubah`), begitu pula `user:table.edit`,
    `role:table.edit`, `user:form.editTitle` (`Edit User`), `role:form.editTitle`;
  - `User`/`Role`/`Permission` sebagai loanword di subtitle, error, placeholder,
    dan empty-state (`Tambah User`, `Cari user`, `daftar role`, `Belum ada role`, dsb.).
  Alasan: `User`/`Role`/`Permission` merujuk ke nama entitas & permission backend;
  menerjemahkan jadi `Pengguna`/`Peran`/`Izin` akan mengaburkan mapping API.
  Bila di masa depan diputuskan melokalkan penuh, ganti serentak + catat di sini.

Contoh:

```tsx
const { t } = useTranslation();
t('common:actions.save'); // Save / Simpan
t('user:table.notFound', { term: search.trim() });
t('common:pagination.total', { count: total, entity, page });
t('validation:passwordMin', { count: 8 });
```

## 5. Cara Tambah Bahasa Baru

1. Tambah kode locale ke `SUPPORTED_LOCALES` di `src/i18n/types.ts`
   (mis. `'ms'`) + update `SupportedLocale` union.
2. Duplikat folder `src/i18n/locales/en/` → `src/i18n/locales/<kode>/`,
   terjemahkan values, **jangan ubah keys**.
3. Daftarkan di `src/i18n/index.ts` (`resources.<kode>` + import JSON).
4. Label switcher: tambah `common:language.<nama>` di semua locale +
   entri `LOCALE_LABEL_KEY` di `language-switcher.tsx`.
5. Verifikasi: `pnpm lint`, `pnpm tsc --noEmit`, test manual EN↔ID↔baru + reload persist.

## 6. Aturan zod-i18n

- Schema zod **di dalam komponen** (bukan module-level) agar pesan bisa pakai `t()`.
- Bungkus schema dengan `useMemo(..., [t])` supaya ikut ganti bahasa.
- Pesan hanya dari `validation:*`:
  `emailRequired/emailInvalid/passwordRequired/passwordMin ({count})/fullNameRequired/nameRequired/passwordMismatch`.
- Contoh:

```tsx
const { t } = useTranslation();
const schema = useMemo(() => z.object({
  email: z.string().min(1, t('validation:emailRequired')).email(t('validation:emailInvalid')),
}), [t]);
```

- Error backend (`ApiError.message`, `errors[]`, `mapApiFieldErrors` dari `@/lib/field-errors`) tidak diterjemahkan — 422 di-map ke `form.setError` per-field (tanpa toast/banner), non-422 tampil apa adanya di banner/toast.
